# BLUE COLLECTOR

**AI와 함께 만든 웹 아케이드 게임**

30초 동안 노란 아이템을 모으고 빨간 추적자를 피하며 높은 점수를 얻는 게임입니다.

플레이어는 안전 모드와 위험 모드(RISK) 중 하나를 선택할 수 있습니다. 위험 모드(RISK)에서는 추가 점수를 얻을 수 있지만, 아이템을 먹을수록 적의 추적 속도가 빨라집니다.

프로그래밍을 배운 적 없는 상태에서 AI로 게임 코드를 만들었습니다. 게임을 직접 플레이하면서 규칙과 화면 구성을 여러 차례 수정했고, 버전마다 플레이 기록(CSV)을 남겼습니다.

## 🎮 PLAY GAME

**[BLUE COLLECTOR 플레이하기](https://moontaku.github.io/blue-collector/)**

별도의 설치 없이 PC 웹브라우저에서 실행할 수 있습니다.

## 2. 조작 방법

- **W / A / S / D 또는 방향키:** 캐릭터 이동 (한글 입력 상태에서도 동작)
- **SPACE:** 안전 모드와 위험 모드(RISK) 전환 (READY 화면에서는 위험 모드 전환 없이 건너뛰기)
- **목표:** 추적자를 피하면서 노란 아이템을 모아 높은 점수 얻기

## 3. 주요 게임 시스템

### 안전 모드와 위험 모드(RISK)

> v1.2.2까지는 "전쟁 모드(WAR)"였고, 이름이 헷갈린다는 의견이 있어 v1.2.3에서 위험 모드(RISK)로 바꿨습니다. 아래 v1.2.0 시기 기록과 CSV 열 이름에는 옛 이름 "전쟁"이 그대로 남아 있습니다.

**안전 모드**

- 기본 점수 획득
- 적의 기본 추적 속도 유지

**위험 모드(RISK)**

- 아이템 획득 점수의 50%를 추가 보너스로 적립
- 아이템을 먹을 때마다 적의 추적 속도 5% 증가 (최대 25%)
- 아이템을 먹고 2초를 살아남아야 안전 모드로 복귀 가능
- 안전 모드로 돌아오거나 30초를 완주하면 적립한 보너스 확정
- 보호막 없이 적과 충돌하면 확정되지 않은 보너스 손실

### 콤보 시스템

4초 안에 다음 아이템을 먹으면 콤보가 이어집니다. 콤보가 쌓이면 최대 3배의 점수를 얻을 수 있습니다.

### NEAR MISS

적과 충돌하지 않고 가까이 지나가면 +20점을 얻습니다.

- 적마다 2초 쿨다운, 한 판 최대 10회
- 콤보 배수와 위험 보너스는 적용하지 않고, 코인 기준 점수에는 포함

### 적 등장 예고

10초와 20초에 새 적이 나타납니다. 등장 1초 전에 붉은 점선 프레임으로 위치를 표시하고, 표시한 위치는 바뀌지 않습니다.

### 코인과 보호막

- 게임이 끝나면 기본 획득 점수만큼 코인 지급
- 코인으로 1회용 보호막 구매 가능
- 보호막은 위험 모드(RISK)에서 적과 충돌했을 때만 발동
- 보호막 발동 시 충돌 1회를 막고 1초 동안 무적 상태 유지

### 개인 기록과 도전 과제

최고 점수, 최고 콤보, 누적 플레이 횟수와 도전 과제를 확인할 수 있습니다.

일부 기록과 보유 재화는 브라우저의 로컬 저장소에 저장됩니다.

## 4. AI와 함께 게임을 만든 과정

이 프로젝트를 시작하기 전에는 프로그래밍 경험이 없었습니다. 게임의 규칙과 필요한 기능을 정하고, AI에 코드 작성을 요청하는 방식으로 개발했습니다.

**직접 한 일**

- 게임 콘셉트와 기본 규칙 기획
- 안전 모드와 위험 모드(RISK)의 보상 및 위험 구조 설계
- 기능별 요구사항 정리
- AI가 작성한 코드를 실행하고 작동 여부 확인
- 직접 플레이하면서 오류와 불편한 부분 기록
- 버전별 플레이 기록(CSV)을 모아 점수, 완주율, 사망 시점 비교
- 수정 방향 결정 및 재테스트

**AI가 도운 작업**

- HTML, CSS, JavaScript 코드 작성 및 수정
- 오류 원인 분석과 수정 방법 제안
- UI 코드 작성과 수정

처음부터 모든 기능을 만들지는 않았습니다.

캐릭터 이동과 아이템 수집부터 시작해 적의 추적, 콤보, 위험 모드(RISK), 상점, 보호막을 차례로 추가했습니다.

기능을 추가할 때마다 직접 플레이해 문제를 찾고, 코드를 수정한 뒤 다시 테스트했습니다.

## 5. 플레이 테스트와 수정 사례

### ① 적의 추적 속도와 난이도

초기 테스트에서 적이 느리게 움직일 때 오히려 아이템을 먹기 어려운 상황을 발견했습니다.

적이 아이템 근처에 오래 머물면서 수집을 방해했기 때문입니다.

추적 속도가 빠르다고 반드시 아이템을 먹기 어려운 것은 아닐 수 있다고 생각해 추가 테스트를 했습니다.

하지만 테스트 결과가 일정하지 않았습니다. 따라서 추적 속도와 체감 난이도 사이의 관계는 아직 확인되지 않은 가설로 남겨두었습니다.

### ② 보호막과 무적 시간

보호막은 적과 충돌했을 때 한 번 살아남도록 만든 아이템입니다.

그런데 직접 플레이해 보니, 보호막이 발동한 1초 동안 평소보다 적극적으로 아이템을 모으게 됐습니다.

반대로 무적 상태가 끝나는 순간 적과 충돌해 게임이 종료되는 경우도 있었습니다.

처음에는 무적 시간이 끝나기 직전에 캐릭터가 깜빡이도록 만들었습니다.

하지만 1초라는 짧은 시간에 깜빡임까지 더해지니 화면이 정신없게 느껴졌습니다.

이후 깜빡임을 없애고 보호막을 나타내는 링이 서서히 사라지도록 수정했습니다.

### ③ 게임 화면의 가독성

플레이 테스트 중 콤보 메시지가 안전 모드와 전쟁 모드 정보를 표시하는 박스에 겹치는 문제를 발견했습니다.

콤보 메시지의 중앙 정렬은 유지하고, 위치를 아래로 28px 옮겼습니다.

또한 위험도 진행 바가 UI 카드의 둥근 모서리 밖으로 튀어나오는 문제도 발견했습니다.

진행 바가 카드 밖으로 보이지 않도록 CSS를 수정하고 화면을 다시 확인했습니다.

### ④ 디자인 개편 (v1.1.0)

이전 화면이 일반적인 AI 생성 웹 디자인처럼 보인다는 의견이 있었습니다. 메뉴도 화면 아래쪽의 작은 글씨라 눈에 잘 띄지 않았습니다.

그래서 파랑은 플레이어, 노랑은 보상, 빨강은 위험으로 색의 의미를 정하고 픽셀 아케이드 스타일로 화면을 다시 만들었습니다. 이모지를 없애고, 메뉴는 버튼으로 바꿔 메인 화면과 하위 화면으로 나눴습니다.

이 버전에서는 게임 규칙을 바꾸지 않았습니다.

### ⑤ 적의 등장 위치와 겹침 (v1.2.0)

어디서 적이 나올지 알 수 없어 갑자기 위험해진다는 의견이 있었습니다. 그래서 새 적이 나타나기 1초 전에 위치를 표시하도록 했습니다.

처음에는 플레이어가 예고 위치에 가까이 가면 예고를 취소하고 다른 곳에서 적을 등장시켰는데, 이 방식이 오히려 당황스럽다는 의견을 받았습니다. 그래서 표시한 위치를 끝까지 유지하도록 고쳤습니다. 이 경우 플레이어가 예고 지점에 서 있으면 등장 직후 충돌할 수 있어서, 이 부분이 지나치게 불합리하지 않은지 계속 확인할 과제로 남겼습니다.

적이 서로 겹치면 최대 3마리가 하나처럼 보여 위협이 느껴지지 않는 문제도 있었습니다. 가까운 적에게서 멀어지는 방향을 더해 겹침을 줄였습니다. 적의 속도 상한은 그대로 두었습니다.

### ⑥ NEAR MISS 점수 실험 (v1.2.0)

기존에는 적을 피하는 행동이 생존에만 쓰였습니다. 위험을 감수한 플레이에 작은 보상을 주려고 적과 충돌하지 않고 가까이 지나가면 +20점을 주도록 했습니다. 측정하기 전에 판단 기준(전체 점수 중 비중, 상한 도달 판 수)을 먼저 정했습니다.

- NEAR MISS를 의식하지 않고 한 30판에서 NEAR MISS 점수는 전체 점수의 약 6%였고, 판당 평균 약 2.5회 발생했습니다.
- 일부러 노린 10판은 평균 477점, 완주율 40%로, 의식하지 않은 안전 모드 15판(평균 743점, 완주율 87%)보다 낮았습니다.

현재 값에서는 노리는 쪽이 손해라서, 새로운 점수 경로라기보다 작은 덤에 가깝습니다. 다른 플레이어를 대상으로 한 테스트는 아직 하지 않았습니다.

## 7. 플레이 테스트 기록

아래 표는 제가 직접 플레이한 기록이며, 보통 난이도와 보호막 없는 조건입니다. 원본 CSV는 [playtests](https://github.com/moontaku/blue-collector/tree/main/playtests) 폴더에 있습니다. 다른 사람이 플레이한 기록도 같은 폴더에 익명(A~I)으로 정리해 두었습니다.

| 버전 | 판 수 | 평균 점수 | 30초 완주율 |
|---|---|---|---|
| v1.0.0 | 안전 10판 / 전쟁 12판 | 390 / 321 | 40.0% / 41.7% |
| v1.2.0 | 안전 15판 / 전쟁 15판 | 743 / 898 | 87% / 60% |

- v1.0.0에서는 두 모드의 차이를 구분할 수 없었습니다. v1.2.0에서는 전쟁 모드가 평균 155점 높았지만 15판씩으로는 우연과 구분되지 않는 수준입니다.
- 두 버전은 규칙이 달라서 위 숫자를 직접 비교하면 안 됩니다. 같은 사람이 계속 플레이해 숙련도도 섞여 있습니다.
- 1,000점 이상은 v1.2.0에서 전쟁 모드 8판, 안전 모드 0판이었습니다.
- 한 명의 플레이어 데이터이고 표본이 작습니다.

### ⑦ 처음 해 본 사람들의 반응 (v1.2.1-test ~ v1.2.4-test)

여기까지는 직접 플레이한 기록만 있었습니다. 이후 온라인 커뮤니티에서 처음으로 다른 사람들의 플레이를 받았습니다. CSV를 보내 준 사람이 8명(한 명은 두 버전에서 플레이), 텍스트 후기만 보낸 사람이 5명입니다. 모집 경로가 한정되어 있고 표본이 작아서, 아래 내용은 "이런 문제가 있었다"는 관찰이며 비율이나 평균으로 단정하지 않습니다.

| 상점을 찾지 못했거나, 오래 플레이했는데 코인(약 29,450개)을 쓰지 않음 | 2명 | 결과 화면에 HOW TO PLAY 추가. 상점의 쓸모는 다음 과제 |
| 보너스를 확정하지 않고 죽는 경우가 많음. 익숙한 사람은 충돌 직전에 먼저 안전 복귀 | 2명 / 1명 | 확정 가능한 순간 강조(v1.2.4-test) |

특히 64판을 플레이한 한 명은 위험 모드에서 충돌한 31판 중 22판에서 먼저 안전 모드로 돌아와 보너스를 확정했고, 잃은 점수 비중이 약 15%였습니다. 처음 해 본 사람들은 70~85%를 잃었습니다. 이 규칙을 이해하면 위험을 관리할 수 있다는 단서이지만, 한 명의 기록입니다.

1,000점 이상은 외부 플레이어에게 드물었습니다(64판 한 명은 1판, 11판 한 명은 2판, 어려움 난이도 한 명은 3판). 직접 플레이할 때는 어렵지 않다고 생각했던 부분이라, 점수 기준과 난이도 판단은 아직 외부 데이터가 부족합니다.

### ⑧ 낮은 FPS와 성능 수정 (v1.2.4-test)

한 테스터의 2019년형 맥북에서 안전 모드 약 33 FPS, 위험 모드 약 27 FPS가 나왔습니다. 프레임이 50ms를 넘는 구간은 위험 모드에서 훨씬 많았고, 아이템을 많이 먹은 판일수록 늘었습니다.

코드를 확인해 보니 아이템을 먹을 때마다 새 위치를 정하면서 화면 요소의 위치를 읽는 호출이 후보마다 반복되고 있었습니다. 읽기를 한 번으로 줄이고, 매 프레임 실행하던 HUD 가림 판정은 0.1초마다로 줄였습니다. 같은 조건의 브라우저 테스트에서 위치 읽기 호출이 약 354,000회에서 약 3,400회로 줄었습니다. 게임 규칙은 바꾸지 않았습니다.

다만 실제 체감 개선은 문제가 났던 기기에서 아직 다시 재 보지 못했습니다. 또 이전 버전에서 FPS가 낮은 기기의 점수에는 멈춤의 영향이 섞여 있을 수 있어서, 난이도 판단에는 조심해서 써야 합니다. 이를 구분하려고 CSV에 화면 배율, 화면 크기, 주사율 등 기기 열을 추가했습니다.

### 외부 플레이어 테스트 (v1.2.1-test ~ v1.2.3-test)

CSV 8명, 텍스트 후기 5명으로 위 ⑦에 정리했습니다. v1.2.4-test부터 CSV에는 `device_pixel_ratio`, `canvas_css_size`, `hardware_concurrency`, `effects_enabled`, `display_hz` 열이 추가됩니다. 외부 플레이어의 원본 CSV는 익명(A~I)으로 [playtests](https://github.com/moontaku/blue-collector/tree/main/playtests) 폴더에 있습니다.

## 8. 개발 결과와 회고

AI로 첫 게임 코드를 만든 뒤 적의 추적, 위험 모드, 콤보, 상점과 보호막 등의 기능을 추가했습니다.

이후 플레이 테스트를 거쳐 UI와 게임 규칙을 수정했고, 완성한 게임을 GitHub Pages에 배포했습니다. 버전마다 릴리즈와 CSV를 남겨 어떤 변경이 어떤 기록과 대응하는지 확인할 수 있게 했습니다.

게임을 만드는 동안 기능이 정상적으로 작동하는지뿐 아니라, 실제로 플레이했을 때 어떤 경험을 주는지도 함께 확인했습니다.

처음 정한 게임 규칙도 직접 플레이해 보니 예상과 다르게 작동하는 부분이 있었습니다. NEAR MISS처럼 의도한 효과가 기록에서는 확인되지 않은 경우도 있었고, 그 결과도 그대로 남겨 두었습니다.

외부 플레이어의 반응을 받고 나서는, 규칙을 아는 제가 쉽다고 느낀 부분이 처음 해 보는 사람에게는 그렇지 않다는 것도 알게 됐습니다. 적을 아이템으로 착각하거나 화면 구석을 못 가는 곳으로 여기는 식이었습니다. 이런 문제는 제가 아무리 다시 플레이해도 보이지 않았습니다.

특히 보호막을 사용했을 때 플레이 방식이 달라지는 점이나, 적의 추적 속도가 아이템 획득에 미치는 영향은 게임을 직접 실행하면서 발견한 문제였습니다.

## 9. 사운드 크레딧

- **BGM:** BLUE COLLECTOR를 위해 새로 만든 곡입니다. AI의 도움을 받아 Python 기반 오디오 합성으로 생성했습니다.
- **파일:** `blue-collector-bgm-original.wav`
- **효과음:** 별도 음원 파일 없이 게임 코드에서 Web Audio API로 생성합니다.
- **외부 음원과 샘플:** 기록된 제작 과정에서는 사용하지 않았습니다.
