# BLUE COLLECTOR · 디자인 결정 및 개발자 노트 (2026-11-16)

> 포트폴리오용 기록. 실제로 관찰된 피드백, 기획 판단, 구현 여부, 향후 가설을 구분한다. AI가 작성한 코드를 지원자가 직접 프로그래밍했다고 주장하지 않는다.

## 이번 리디자인을 결정한 이유

- **관찰된 사용자 피드백:** 이전 UI는 정돈되었지만 일반적인 AI 생성 웹 디자인처럼 보인다는 의견이 있었다. 메뉴( HOW TO PLAY, RECORDS, SHOP, SETTINGS )가 화면 하단의 작은 텍스트로 배치돼 잘 발견되지 않았다.
- **지원자의 직접 제안:** 첨부한 고전 게임 시작 화면처럼 픽셀/레트로 아케이드 방향으로 바꾸고, 한 화면에 정보를 모두 담지 말고 메인 스타트 화면과 개별 메뉴 화면을 나누자.
- **유지하고 싶은 점:** 기존 메인 화면 뒤에서 파랑 플레이어, 노랑 아이템, 빨강 추적자가 움직이는 데모 연출은 좋았다. 따라서 모션은 유지하고 장식과 정보 밀도를 줄인다.
- **판단:** 게임 자체가 단순 도형·세 가지 의미색으로 구성되므로 픽셀 그래픽이 콘셉트와 연결된다. 레퍼런스 이미지를 그대로 복제하지 않고 도형·배치·타이포는 독자적으로 만든다.

## 디자인 원칙

1. **파랑 = 플레이어**, **노랑 = 보상/점수**, **빨강 = 적/위험**. 중립색은 배경·본문 용도로만 사용한다.
2. 이모지, 둥근 카드 반복, 네온 글로우/그라데이션/유리 효과를 피한다. 픽셀/직선/각진 프레임을 활용한다.
3. 가장 먼저 보일 요소는 게임명과 START GAME. 나머지 메뉴는 *작은 텍스트 링크가 아니라 식별 가능한 버튼*으로 표현한다.
4. **화면 계층을 분리:** 1단계 메인 메뉴 / 2단계 HOW TO PLAY·RECORDS·SHOP·SETTINGS. 기존 게임과 결과 화면은 별도.
5. 복잡한 그래픽 리소스나 외부 폰트에 의존하지 않는다. 도트 로고를 직접 픽셀 패턴으로 그리고 기본 시스템 텍스트를 사용한다.

## REDESIGN 02 구현 범위

- 메인 화면을 픽셀 아케이드 구조로 재작성. `START GAME` 주 버튼, 네 가지 동급 메뉴 버튼, 난이도 선택을 명확히 분리.
- HOW TO PLAY / RECORDS / SHOP / SETTINGS를 같은 세계관의 **전체 화면 서브 페이지**로 스타일링. 각 페이지에 `BACK` 제공.
- 배경 자동 시연은 유지. 본 게임의 점수·생존 시간·코인에는 개입하지 않음.
- 설정 페이지에서 SFX / MUSIC ON·OFF 조작 제공(기존 오디오 토글과 연동).
- 현재 게임 규칙(30초, 콤보 4초, 안전/전쟁 전환, 적 속도, 코인·보호막)은 수정하지 않음.
- 원본 플레이어 상태는 브라우저 `localStorage` 키를 유지해 보존. 이번 ZIP에서 신규 저장 데이터 포맷 도입 없음.
- Github 공개 배포는 사용자 확인 전까지 수정하지 않음.

## 플레이 피드백과 후속 검토 과제 (이번 버전에서 미구현)

### 생성·공정성
- **관찰:** 어디서 적이 생성되는지 몰라 외곽으로만 움직이거나 빠르게 죽었다는 의견이 있었다.
- **기획 후보:** 새 적이 등장할 위치에 1초 전 빨간색 예고 프레임을 표시. 예고한 위치와 실제 등장 위치가 같아야 하며, 플레이어가 그 위치로 이동한 경우의 처리 조건을 정해야 한다.
- **기획 후보:** 아이템과 적의 생성 간격 확대. 적의 선호거리 260px을 무조건 강제하면 생성 지연이라는 다른 문제가 생길 수 있으므로 별도 실험 필요.

### 콤보
- **관찰:** 콤보 유지 시간 4초가 애매하다는 피드백이 있었다.
- **기획 판단:** 목숨 1개의 30초 게임이라 콤보 시간을 단순 삭제하면 연속 수집이 누적 카운터처럼 변할 수 있다. 시간 제한 삭제는 아직 보류. 콤보 남은 시간의 시각적 피드백을 먼저 검토한다.

### 전쟁 모드
- **제안:** SPACE 또는 다른 키를 길게 누르는 동안 전쟁 모드 유지. 전쟁 시 플레이어·적 속도 변화 또는 별도 적 제거 액션.
- **검토:** 홀드 조작은 기존 '마지막 전쟁 아이템 획득 후 2초 생존해야 안전 복귀' 규칙과 충돌한다. 실제 조작과 보상 루프를 다시 설계한 뒤 검증해야 하므로 미구현.
- **제안:** 추가 점수 획득 방식(근접 회피/NEAR MISS 등)을 통해 개인 최고점 갱신의 동기를 강화. 점수 악용 방지 조건 및 밸런스 검증 필요. 미구현.

### 게임 밸런스/경제
- **1차 데이터:** 안전 모드 10판, 전쟁 모드 12판의 소규모 테스트가 있었다. 초반 사망 포함 전쟁 모드의 우월성은 확정할 수 없었다. 수정 전 기록은 기준 데이터로 보존한다.
- **제안:** 전쟁 보너스 비율을 0.5에서 0.8로 바꾸는 실험. 현재는 기획 가설로만 남기고 미구현.
- **경제:** 한 판 기본 점수를 코인으로 지급, 보호막 1,000코인/최대 3개. 소비처가 제한적이라는 피드백은 유효하나 이번 UI 변경에서 경제 수치를 조정하지 않는다.
- **측정 보강 후보:** 아이템 총 획득 수, 모드별 플레이 시간, 모드 전환·보너스 확정 횟수, 적 등장 전후 사망 시점.

## 포트폴리오용 설명 초안

> 초기 테스트에서 메뉴가 눈에 잘 띄지 않고 화면의 정보량이 많아 게임보다 웹 UI처럼 보인다는 의견을 받았다. 이에 플레이어(파랑), 보상(노랑), 위험(빨강)을 디자인 기준으로 정하고, 메인 화면과 메뉴 화면을 분리했다. 움직이는 도형 배경은 유지하되 메뉴의 우선순위를 명확히 했으며, 기존 플레이 시스템은 변경하지 않고 시각적 리디자인 효과를 확인할 수 있도록 구성했다.

**유의:** 이 설명은 디자인 변경의 *의도와 구현*을 기록한다. 외부 플레이어의 가독성/완성도 평가가 개선되었다는 결론은 새 버전 테스트 후에만 추가한다.

## 테스트 기록 (2026-11-16)

- Chrome 계열 브라우저 렌더링 검증: 960×540 PC 기준 메인 메뉴, 게임 방법, 기록, 상점, 설정 화면 캡처 및 육안 확인.
- 조작 검증: 최초 START → 게임 방법 → 실제 게임 진입 / 재진입 시 안내 생략 / SPACE 안전·전쟁 전환 / 결과 화면 → 메뉴 복귀 / 보호막 구매 시 코인 차감 / SETTINGS 사운드 토글.

- 브라우저 보안 정책으로 직접 파일 URL 이동이 제한되어 동일한 HTML·CSS·JavaScript를 인라인으로 주입해 검증함. 따라서 WAV 실제 재생, 각 OS/브라우저의 파일 접근은 별도 사용자 확인이 필요함.
- 게임의 정식 타깃은 **PC 웹브라우저**. 모바일에서는 960×540 게임 스테이지가 축소되어 UI가 작게 보이므로 모바일 사용성은 개선 대상에 포함하지 않음.
- **미변경:** 인게임 HUD 및 결과 화면의 기존 시각 디자인. 다음 디자인 단계에서 통일 필요.


## REDESIGN 03 — 첫 진입 인트로 픽셀 스타일 통일 (2026-11-16)

- **사용자 문제 제기:** 메인 메뉴와 서브 메뉴를 픽셀 아케이드로 개편했지만, 첫 접속 시 표시되는 기존 인트로가 모던 UI로 남아 톤앤매너가 단절되었다.
- **사용자 의사결정:** 먼저 인트로를 수정하고, 다음 단계에서 인게임 HUD와 결과 화면을 정리한다.
- **이번 구현:** 기존 `YOU → COLLECT → SURVIVE → BLUE COLLECTOR` 4단계 메시지 유지. 프레임·픽셀 도형·도트 글리프·색상·순차 진행 표시를 메인 메뉴와 연결했다. 과도한 네온 글로우 및 전체 화면 점멸은 제거. 약 3.0초, SPACE/Enter/Escape/버튼으로 스킵 가능.
- **범위 통제:** 게임 시작 버튼과 첫 플레이 안내 팝업의 순서, 점수·콤보·적 생성·코인·보호막·BGM 및 저장 데이터는 변경하지 않음. 새로운 인게임 HUD는 이 버전에 포함되지 않음.
- **확인할 점:** 인트로의 첫인상, 3색 의미 전달, 메인 메뉴와의 연결감, 실제 브라우저에서의 시각적 깨짐 여부. 이러한 개선 효과는 사용자 테스트 전에는 확정하지 않음.


## REDESIGN 04 — 배경색/픽셀 레터링 무게 조정 (2026-11-16)

- **사용자 피드백:** PIXEL ARCADE V3는 레트로 방향은 맞지만 파란 기운이 강하고, 타이틀 폰트가 산만하다. 사용자가 제공한 고전 게임의 `PRESS START` 레퍼런스처럼 더 두껍고 정돈된 픽셀 글자를 원했다.
- **디자인 결정:** 레트로 무드는 파란 배경이 아니라 각진 프레임, 픽셀 타이포, 제한된 의미색, 도형 모션에서 유지한다. 따라서 전반적 배경색을 흑색에 가까운 중립색 `#0B0B10`으로 변경하고, 패널은 `#131318` 근방의 중립색으로 변경했다. 세 가지 포인트 색은 파랑(나), 노랑(보상), 빨강(위험)으로 유지한다.
- **시각 변경:** 자체 5×7 비트맵 타이틀의 획을 두껍게 다듬고 노랑 글자에 짧은 붉은 픽셀 그림자를 적용해 첨부 레퍼런스의 구조를 참고하되 원본 게임의 이름/그래픽으로 새로 구성했다. 영문 메인 메뉴 글자도 획을 소폭 두껍게 조정했다. 메인·인트로·HOW TO PLAY·RECORDS·SHOP·SETTINGS에 같은 중립 배경을 적용했다.
- **범위:** 게임 플레이 HUD, 결과 화면, 게임 룰, 생성/콤보/전쟁 모드, BGM, 저장 데이터 키는 이번 단계에서 변경하지 않았다. 신규 외부 폰트 파일은 사용하지 않았다.
- **검증 예정:** 960×540 PC, 큰 창과 좁은 창에서 글자 잘림과 메뉴 클릭 동작, 인트로 4단계, 메인 진입, 실제 게임 시작을 확인한다.
- **미반영:** GitHub에는 사용자 확인 전까지 업로드하지 않음.


## REDESIGN 04.1 — 인트로/메인 프레임 일치 및 타이틀 컬러 복구 (2026-11-16)

- **사용자 피드백:** 동일한 게임인데 인트로의 흰색 테두리와 메인 화면의 흰색 테두리가 서로 다른 크기로 표시됨. 메인 BLUE COLLECTOR 로고가 노랑으로 바뀐 것이 이름과 색상 상징에 어긋남. 타이틀 글자는 이전 버전처럼 좌정렬 선호.
- **확인된 원인:** 인트로 프레임 컨테이너 최대 너비가 1150px, 메인 화면은 1180px이었고 패딩·헤더·푸터 및 최대 높이도 서로 달랐다. V4의 자체 5×7 픽셀 글리프 렌더러에서 글자면을 노랑(#F5CF37)으로 바꾸고 BLUE 및 COLLECTOR의 가로 시작점을 중앙에 가깝게 옮겼다.
- **수정 결정:** 인트로 프레임을 메인 화면과 같은 너비·높이·여백 규칙으로 맞춰 화면 전환 시 테두리 점프를 방지한다. 로고는 밝은 파랑(#5E91FF)과 짙은 파란 픽셀 그림자를 사용한다. BLUE / COLLECTOR 두 줄의 시작 x좌표를 모두 8로 맞춰 왼쪽 정렬한다. 인트로 마지막 로고는 이 메인 로고 캔버스를 공유하므로 색상도 함께 통일된다.
- **수정 범위:** CSS 프레임 레이아웃과 JS 타이틀 비트맵 드로잉만 변경. 기존 3색 장면 순서, 메뉴, 실제 게임 로직, 상점, 기록, 사운드/BGM, 저장 데이터는 그대로 유지.
- **배포:** 테스트 ZIP만 제작하며 GitHub 배포에는 반영하지 않음.
- **QA 추가 조정:** 과거 인트로에 남은 둥근 보조 테두리를 제거하고, 760px 이하 좁은 화면에서는 SKIP 버튼 포커스가 화면을 자동 스크롤해 프레임을 이동시키던 문제를 preventScroll 옵션으로 방지.


## 2026-11-16 — REDESIGN 05: 인게임 HUD 시각 통일 (테스트 버전)

- **사용자 승인:** 픽셀 레트로 메인 화면 및 HOW TO PLAY·RECORDS·SHOP·SETTINGS 메뉴는 V4.1 기준 통과. 승인된 영역은 변경하지 않기로 결정.
