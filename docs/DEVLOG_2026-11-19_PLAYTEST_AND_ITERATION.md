# BLUE COLLECTOR · 외부 플레이테스트와 개선 개발자 노트

**기록일:** 2026-11-19  
**대상 버전:** v1.2.0 ~ v1.3.0  
**개발 방식:** 직접 기획 및 테스트, AI를 활용한 코드 구현·수정

## 1. 외부 플레이테스트를 진행한 이유

게임을 직접 제작하고 반복해서 플레이하면서 기본적인 조작과 규칙에 익숙해졌습니다. 하지만 제가 이해하고 있는 규칙을 처음 플레이하는 사람도 자연스럽게 이해할 수 있는지는 확인하지 못했습니다.

이를 검증하기 위해 외부 플레이어에게 게임을 제공하고, 플레이 기록(CSV)과 주관적인 후기를 수집했습니다.

테스트 과정에서 플레이어의 행동과 실제 피드백을 구분해 기록하고, 발견한 문제를 다음 버전에 반영했습니다.

## 2. 발견한 문제와 개선

### ① 게임 규칙의 이해 문제

**관찰**

일부 플레이어는 빨간 추적자를 피해야 할 대상으로 인식하지 못했고, 위험 모드에서 적립한 보너스를 안전 모드로 돌아와 확정할 수 있다는 사실도 이해하지 못했습니다.

게임의 규칙을 알고 있는 제작자와 처음 접하는 플레이어 사이에 이해도 차이가 있다는 것을 확인했습니다.

**판단 및 개선**

게임의 핵심 보상 구조를 곧바로 변경하기보다, 기존 규칙이 제대로 전달되고 있는지부터 점검했습니다.

첫 플레이 안내와 위험 모드 설명을 보완하고, 보너스를 확정할 수 있는 순간을 화면에서 더 명확하게 표시했습니다. 또한 WAR라는 명칭이 혼란스럽다는 의견을 반영해 RISK로 변경했습니다.

이 과정에서 점수와 충돌 판정 등의 게임 규칙은 유지하고 안내와 표시를 중심으로 수정했습니다.

### ② 화면 구성과 조작의 문제

**관찰**

일부 플레이어는 화면 왼쪽 위 HUD 영역을 이동할 수 없는 구역으로 오해했습니다. 한글 입력 상태에서 WASD 키가 작동하지 않는 문제도 확인했습니다.

**판단 및 개선**

HUD의 크기를 줄이고 반투명하게 표현하여 실제 플레이 영역과 구분되도록 수정했습니다.

키 입력은 입력된 문자보다 물리적인 키 위치를 기준으로 판단하도록 변경했습니다.

시각적 안내와 입력 방식이 플레이 경험에 직접적인 영향을 줄 수 있다는 점을 확인했습니다.

### ③ 성능 문제

**관찰**

한 외부 테스터의 기기에서 안전 모드와 위험 모드의 FPS가 낮게 측정됐습니다. 위험 모드에서는 프레임 저하가 더 심하게 나타났습니다.

**원인 분석 및 개선**

AI와 함께 코드를 검토한 결과, 아이템 위치를 결정하는 과정에서 화면 요소의 위치를 반복적으로 읽는 호출이 발생하고 있었습니다.

해당 호출을 줄이고 매 프레임 실행하던 일부 HUD 판정을 일정한 간격으로 실행하도록 수정했습니다.

같은 조건의 브라우저 테스트에서 관련 위치 읽기 호출이 약 354,000회에서 약 3,400회로 감소했습니다.

다만 최초 문제가 발생했던 기기에서 개선 후 FPS를 다시 측정하지 못했으므로, 실제 성능 개선 효과는 아직 확정하지 않았습니다.

## 3. AI와 사람의 역할 분담

게임을 제작하는 과정에서 모든 판단을 AI에 맡기지 않으려고 했습니다.

**직접 담당한 부분**

- 플레이 중 발견한 문제와 외부 피드백 정리
- 문제의 원인에 대한 가설 설정
- 변경할 기능과 유지할 규칙 구분
- AI에 전달할 수정 요구사항 작성
- 수정 결과 확인 및 플레이테스트
- 다음 버전에 반영할 내용 결정

**AI를 활용한 부분**

- HTML, CSS, JavaScript 코드 작성 및 수정
- 오류 원인 분석과 해결 방법 제안
- UI 및 입력 처리 개선
- 반복 호출 등 성능 문제의 수정 지원

특히 플레이어에게 규칙이 전달되지 않는 문제를 해결할 때는 게임 규칙 자체와 안내 방식의 문제를 구분하려고 했습니다.

수정 범위를 제한하고 기존 규칙이 유지되는지 확인하는 방식으로 작업했습니다.

## 4. 테스트에서 확인하지 못한 부분

### 상점과 보호막

외부 플레이테스트에서는 기록 비교를 위해 보호막 사용을 제한했습니다. 따라서 실제 플레이에서 상점과 보호막이 얼마나 사용되는지는 확인하지 못했습니다.

다만 상점을 몇 판 뒤에야 발견했다는 피드백이 있었고, 보호막은 위험 모드에서만 작동하기 때문에 위험 모드를 이용하지 않는 플레이어에게 구매 동기가 부족할 가능성이 있습니다.

다음 테스트에서는 보호막 사용을 허용하고 상점 발견, 구매, 실제 사용까지 확인할 계획입니다.

### 테스트 결과의 한계

외부 테스터는 제한된 경로에서 모집했으며, 테스트 버전과 플레이 횟수도 동일하지 않습니다.

일부 개선은 같은 플레이어의 반복 플레이 과정에서 확인했기 때문에 게임에 익숙해진 효과를 분리하기 어렵습니다.

따라서 이번 결과는 전체 유저에게 적용할 수 있는 통계적 결론보다, 실제 플레이에서 문제가 발생했다는 관찰과 후속 개선의 근거로 사용했습니다.

## 5. 개발을 통해 배운 점

이번 프로젝트를 시작할 때는 게임 규칙과 기능을 구현하는 데 집중했습니다.

하지만 외부 플레이어의 기록과 피드백을 확인하면서, 의도한 기능이 정상적으로 작동하는 것과 플레이어가 그 기능을 이해하고 활용하는 것은 다른 문제라는 사실을 알게 됐습니다.

또한 AI를 통해 코드를 빠르게 작성할 수 있더라도, 무엇을 수정해야 하는지 판단하고 수정 결과를 검증하는 일은 직접 책임져야 한다는 점을 경험했습니다.

앞으로는 새로운 기능을 추가하는 것뿐 아니라, 기존 시스템이 실제 플레이에서 어떤 역할을 하는지 확인하고 그 결과를 바탕으로 개선하는 데 집중하고자 합니다.
